01探索方向

从三个真实问题开始。

把授权放在 AI 与外部世界交互的地方。
以下是我们希望共同探索的应用方向。

探索方向 01

Agent 可以调用哪些工具？

在工具真正执行之前，根据用户身份、Agent 角色与任务上下文，检查这次调用是否被允许。

例如

可以查询订单，
退款操作需要单独授权。

  • Tool calling
  • MCP 场景
探索方向 02

哪些知识可以进入上下文？

在检索或返回知识之前检查访问权限，让文档、租户与数据范围的边界延续到 AI 问答中。

例如

同一个问题，
只检索当前用户有权访问的资料。

  • RAG
  • Knowledge access
探索方向 03

协作的 Agent 如何划分权限？

探索将发起用户、执行 Agent 和运行上下文映射到授权请求，为不同职责定义不同的访问范围。

例如

研究 Agent 读取资料，
执行 Agent 在授权范围内写入。

  • Multi-agent
  • RBAC / ABAC

这些是应用探索方向。具体集成需要由应用或适配层接入 Speedle；本页不代表已发布的 MCP、RAG 或 Agent 集成产品。

03接入思路

把授权接入行动链路。

应用在访问数据或执行工具之前请求授权，
并根据返回的决定执行操作。

  1. 01

    描述身份与上下文

    确定是谁发起请求、由哪个 Agent 执行，以及所属的用户、角色与租户。

    subject
  2. 02

    映射资源与操作

    将工具、文档或业务对象映射为资源，将读取、导出或写入映射为操作。

    resource · action
  3. 03

    请求策略决策

    向 Speedle 请求授权决定，用可理解、可维护的策略描述访问规则。

    is-allowed
  4. 04

    在应用中落实

    由应用执行允许的操作、拦截拒绝的操作，并记录自身的执行结果。

    allowed: true | false
